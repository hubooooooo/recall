# 第二大脑 · 需求文档

> 状态：需求已对齐，待技术设计　|　版本：v0.1　|　日期：2026-11-27
> 定位：Recall 项目，基于 Personal-Agent 底座开发「第二大脑」，把散落在各平台的收藏串联成可回忆、可输出的个人知识体系。

---

## 1. 背景与目标

我在抖音、B 站、X、YouTube、小宇宙上长期收藏大量内容，涵盖 AI 基础知识、人生观点等。这些内容分散在不同平台，收藏后很少再看，也无法互相串联。

**核心目标：帮我串联、回忆起自己的知识体系。** 内容量很大，单纯“存下来、能搜到”不够，关键是：

1. **串联**：不同平台、不同时间收藏的内容，自动按概念和观点连起来。
2. **回忆**：随时能看到“我在某个话题上已经知道什么”，新内容进来时提醒我已有的相关知识。
3. **唤醒**：不让收藏吃灰，定期把新发现的关联、本周收获、该做的行动推给我。
4. **输出**：以自己的收藏为素材，辅助写内容、做课程、想问题、做复盘。

## 2. 范围

### 2.1 本期要做

- 五个平台的采集：抖音、B 站、X、YouTube、小宇宙。
- 新内容的自动同步，加上手动分享作为补充入口。
- 几千条旧收藏的导入。
- 转写、AI 理解、分类、串联、过时标记。
- 网页仪表盘、问答、知识地图、主题页。
- 推送：新关联日报、每周总结、行动提醒、采集故障通知。
- 辅助输出。

### 2.2 本期不做

- **我自己的输出**（写过的文章、讲过的课）：以后要收，本期不收。X 上我自己发的帖除外，见 4.1。
- **小红书、公众号等其他平台**：以后再加，但架构上要预留，见 4.4。
- **分享和多人协作**：只有我一个人用。
- **收藏时的手动批注**：不需要，完全交给 AI 理解。
- **每日间隔重复回顾**：不需要。

## 3. 使用环境

| 项 | 约定 |
|---|---|
| 运行机器 | 一台一直开机的 Mac（Apple 芯片），所有服务和数据都在这台机器上 |
| 用户 | 仅我本人，单用户 |
| 访问设备 | iPhone + 电脑 |
| 访问方式 | 自建网页，经 Tailscale 访问，走 HTTPS；网页可添加到 iPhone 主屏幕，像 App 一样使用 |
| 不使用 | 飞书。也不依赖 Telegram 等需要代理的第三方聊天工具 |

## 4. 内容采集

### 4.1 采集位置：按平台和我的收藏习惯

每个平台我收藏内容的方式不同，采集位置分别配置。**我不需要改变使用习惯**，照常在各平台点收藏、点赞、转推即可。

| 平台 | 我的收藏方式 | 采集位置 | 内容归属 |
|---|---|---|---|
| 抖音 | 收藏 | 我的收藏 | 收藏 |
| B 站 | 收藏 | 收藏夹（可指定哪几个） | 收藏 |
| X | 发帖、转推 | 我自己的主页时间线 | 自己发的帖标记为 **「我的观点」**，转推标记为收藏 |
| YouTube | 点赞 | 「赞过的视频」列表 | 收藏 |
| 小宇宙 | 收藏 / 喜欢 | 本期只用分享单集链接；自动同步待调研 | 收藏 |

X 的引用转推、回复、点赞、书签不在本期范围。

### 4.2 同步

- **定时同步是主入口**，按平台设不同频率：

  | 平台 | 频率 | 原因 |
  |---|---|---|
  | B 站、YouTube、X | 每 1–2 小时 | 接口相对稳定 |
  | 抖音 | 每天 3–4 次 | 降低风控风险 |
  | 小宇宙 | 不自动同步 | 无公开接口，本期只靠分享 |

- **增量同步**：每个采集位置记录上次同步到哪里，只拉新增内容。
- **去重**：同一条内容无论从同步还是分享进来，都只保留一份。
- **同步不消耗 AI 额度**：采集一律用固定脚本，不让大模型去操作浏览器；只有新内容进入处理流程时才调用模型。
- **登录态**：需要登录的平台用 Mac 上已登录的浏览器或保存的登录凭证，只读取我自己账号的收藏，**绝不发帖、点赞或做任何写操作**。

### 4.3 补充入口：手动分享

- iPhone：系统分享菜单里的快捷指令「存入大脑」，把链接发到 Mac。
- 网页：粘贴链接保存。
- 用于不在上述采集位置里的内容，以及小宇宙单集。

### 4.4 可扩展

每个平台做成一个独立的**采集器**，统一约定以下几项：

- 怎么登录，或者不需要登录；
- 从哪里读取；
- 怎么做增量同步；
- 怎么把平台数据转成统一的内容格式。

以后加小红书、公众号等平台，只新增一个采集器，后续处理流程不用改。

### 4.5 旧收藏导入

各平台累计有几千条旧收藏，采用**先粗后精**的方式：

1. **粗筛入库（全部）**：只用标题、简介、作者、平台、时间等元数据，加上本地向量。几天内全部入库，导入后马上能搜到。
2. **精读（按优先级逐步处理）**：完整走一遍下载、转写、AI 理解、串联。每天限量处理，不挤占日常使用。优先级依次是：最近收藏的 → 与我近期提问的主题相关的 → 其余。
3. **用到时临时精读**：问答命中一条还没精读的内容时，当场补处理。

各平台导入方式：

- **X**：用官方「下载你的数据」一次拿到全部历史，之后转为定时同步。
- **B 站、YouTube**：用接口分页拉取。
- **抖音**：用已登录的浏览器慢速分批读取，分多天完成，避免触发风控。

## 5. 内容处理

### 5.1 流程

```
采集 / 分享 → 去重 → 抓取原文、下载音视频 → 转写 → AI 理解 → 分类 → 串联 → 入库 → 更新主题页
```

### 5.2 各环节要求

| 环节 | 要求 |
|---|---|
| 抓取 | 文字内容取正文和图片；视频和音频只取音轨用于转写 |
| 转写 | 在 Mac 本地运行（SenseVoice 等），中文优先；YouTube 有字幕时直接用字幕；转写稿保留时间戳 |
| AI 理解 | 中文摘要、核心观点、金句、可执行的行动、关键概念 |
| 英文内容 | 保留原文和英文转写稿，摘要、观点、主题页统一用中文 |
| 备份 | 保存正文、转写稿、封面和图片，防止原帖被删后找不到；视频和音频处理完就删除 |

### 5.3 分类

- **大类由我定**，当前四个：
  1. AI 与技术
  2. 人生观点与思维
  3. 商业与个人成长
  4. 教育与内容创作
- **细分主题由 AI 自动生成**，挂在大类下面，随内容增长调整。
- 一条内容可以属于多个主题。

### 5.4 过时标记

- AI 判断每条内容的时效性：AI 工具、版本、价格、行业动态等**易过时**；观点、方法论等**长期有效**。
- 易过时的内容定期复查。
- 有更新的内容推翻旧内容时，把旧内容标为 **「可能已过时」**，附上原因，并链接到新内容。
- 问答和主题页里引用过时内容时要明确提示。

## 6. 串联与回忆（核心）

| 能力 | 说明 |
|---|---|
| **知识地图** | 大类 → 主题 → 概念三层结构，一眼看到知识体系全貌：每个主题有多少内容、最近有没有新增、哪些主题在变热 |
| **自动关联** | 新内容进来时，找出它和旧内容的关系：讲同一概念、观点互相支持、观点互相矛盾。跨平台、跨时间都要能连上 |
| **主题页** | 每个主题一页，汇总所有相关观点及其出处，按时间看我的认识怎么演变。主题页是问答、写作、做课件、复盘的共同起点 |
| **入库时回忆** | 新内容入库时告诉我“你已经知道什么”，例如：“这条讲 RAG，你之前收过 12 条相关内容，核心观点是……” |
| **主动回忆** | 问“我对 X 知道些什么”，按主题给出我已有的观点、出处和时间线 |
| **我的观点** | X 上我自己发的帖单独标记，和收藏的内容一起串联，用来区分“别人说的”和“我自己想的” |

## 7. 使用界面

### 7.1 网页

- **首页是仪表盘**：最近收录、新关联、待办行动、本周热门主题，顶部有提问框。
- **问答**：用自然语言提问，回答基于我的收藏。每个结论都附出处，点击能回到原帖；视频出处直接跳到原视频对应的时间点（B 站、YouTube 支持）。
- **知识地图与主题页**：按大类、主题浏览。
- **内容详情**：原文或转写稿、摘要、观点、所属主题、关联内容、过时状态。
- 手机和电脑都要好用。

### 7.2 辅助输出

以主题页和问答为基础，支持以下四类输出，每类都要注明用到的素材出处：

| 类型 | 举例 |
|---|---|
| 写内容 | 公众号文章、小红书笔记、视频脚本 |
| 做课程 | 教案、课件提纲、分享稿 |
| 帮我想问题 | 做决策、理思路时，把相关观点（包括互相矛盾的）翻出来一起讨论 |
| 个人成长复盘 | 看我的关注点和观点随时间怎么变化 |

可以复用 Personal-Agent 现有的草稿和确认卡机制。

## 8. 推送与唤醒

| 推送 | 频率 | 内容 |
|---|---|---|
| 新关联日报 | 每天一次，固定时间 | 只挑当天最有价值的几条关联，不逐条推 |
| 每周总结 | 每周一次 | 本周收获、热门主题、观点变化、行动完成情况 |
| 行动提醒 | 定期 | 从收藏里提炼“可以做的事”，问我做了没有；在仪表盘上标记「完成」或「不做了」 |
| 采集故障 | 即时 | 见第 9 节 |

推送渠道是 iPhone 通知：网页添加到主屏幕后接收推送。推送不稳时用 Bark 等推送 App 兜底。

## 9. 采集故障处理

- 任何采集器失败（登录过期、接口变化、被限流等）都要**立即推送通知**。
- 通知里写清楚失败原因，并给出**推荐的修复方案**。例如“抖音登录过期，请在 Mac 上重新登录”，或“B 站接口字段变化，建议这样修改”。
- 涉及改代码、改配置的修复，**必须经我确认后才执行**。
- 仪表盘上显示每个采集器的状态：上次成功时间、待处理数量、最近一次错误。

## 10. 模型与成本

### 10.1 分工

| 任务 | 承担者 | 原因 |
|---|---|---|
| 转写 | Mac 本地模型 | 免费、隐私，中文效果好 |
| 向量化与检索 | Mac 本地向量模型（如 bge-m3） | 免费、隐私 |
| 摘要、观点、分类 | 本机 Claude Code（`claude -p`，用我的订阅） | 质量好，日常量不大 |
| 串联、主题页、周报 | 本机 Claude Code，可直接读写知识库文件 | 最需要“思考”的部分 |
| 问答、辅助输出 | 先用向量检索找到相关内容，再交给 Claude Code 生成 | 回答必须附出处 |

### 10.2 要求

- **模型可替换**：通过 Personal-Agent 的 LLM 网关接入。订阅额度不够或需要批量处理时，可以切到 DeepSeek、Kimi 等便宜的 API，或者 Claude 的 Haiku 模型。
- **额度保护**：旧收藏精读每天限量；同步检查本身不调用模型；每天的日报和周报是固定开销。
- **使用订阅的注意事项**：运行环境里不能设置 `ANTHROPIC_API_KEY`，否则会优先走 API 计费；订阅只限我本人使用。

### 10.3 量级参考

- 每天新增：几十条。
- 旧收藏：几千条。

## 11. 隐私与安全

- 所有数据只存在本地 Mac，只有我能访问（经 Tailscale）。
- 收藏的第三方内容一律当作**不可信数据**，内容里的文字不能被当成指令执行，沿用现有的提示注入护栏。
- **与现有原则的关系**：Personal-Agent 现在的原则是“不登录任何网站、无人值守操作”。本模块的采集器需要读取我自己账号的收藏，因此：
  - 采集器作为**独立组件**运行在 Agent 之外，只负责读取我自己账号的收藏并写入内容库；
  - 采集器**只读**，绝不发帖、点赞或做任何写操作；
  - Agent 本身保持现有的只读和确认原则不变；
  - README 的「做 / 不做」表需要相应更新说明。

## 12. 与底座（Personal-Agent）的关系

Recall 是从 Personal-Agent 0.8.2 复制出来的独立项目，此后独立演进。Personal-Agent 仓库本身保持不动，作为以后其他项目的底座。

在 Recall 里保留并整合底座的现有功能，第二大脑作为新模块加入。

| 现有能力 | 在第二大脑中的用途 |
|---|---|
| LLM 网关 | 接入 Claude Code 和备用模型，失败时自动降级 |
| 向量检索（sqlite-vec + bge-m3 + 混合排序） | 内容检索、关联发现 |
| 定时任务与主动推送 | 同步调度、日报、周报、行动提醒 |
| 爬取模块 | 网页正文抓取、RSS |
| 工具注册表 | 注册内容检索、回忆、输出类工具 |
| 个人档案记忆 | 帮助 AI 理解我，让串联和输出更贴合 |
| 草稿和确认卡 | 辅助输出的定稿流程，以及修复方案的确认 |
| 网页前端 | 在现有基础上新增仪表盘、知识地图、主题页 |
| 不可信内容护栏 | 防止收藏内容中的提示注入 |

不再使用的部分：飞书渠道。代码保留，本模块不依赖它。

## 13. 分期

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| **第一期：跑通主链路** | 分享链接 → 转写 → AI 理解 → 分类 → 入库 → 自动关联；网页仪表盘和问答（带出处） | 分享一条 B 站视频，几分钟内能在网页上看到摘要、所属主题、关联内容，并能针对它提问 |
| 第二期：知识体系 | 知识地图、主题页、入库时回忆、过时标记 | 能看到四个大类下的主题结构；问“我对 X 知道些什么”能得到带时间线的回答 |
| 第三期：自动同步 | B 站、YouTube、X 采集器；故障通知 | 照常在平台上收藏，1–2 小时内自动入库；采集器失败时 iPhone 收到通知和修复建议 |
| 第四期：旧收藏与抖音 | 旧收藏粗筛 + 分批精读；抖音采集器；小宇宙可行性调研 | 几千条旧收藏全部可搜，精读按计划推进 |
| 第五期：唤醒与输出 | 新关联日报、每周总结、行动提醒；四类辅助输出 | 每天、每周按时收到推送；能基于某个主题生成带出处的文章初稿或课件提纲 |

## 14. 验收标准（整体）

- 照常在各平台收藏，不改变习惯，内容就能自动进入第二大脑。
- 任何一条收藏都能在网页上通过自然语言找回，回答带可点击的出处。
- 新内容入库时，能指出它与旧内容的关联，至少覆盖跨平台的情况。
- 每个主题页能看到相关观点的汇总和时间演变。
- 过时内容被标出，并链接到更新的内容。
- 采集失败时，能在短时间内收到通知和可执行的修复建议。
- 所有数据只在本地 Mac 上，只有我能访问。

## 15. 待确认 / 风险

| 项 | 说明 |
|---|---|
| 小宇宙自动同步 | 没有公开接口，需要调研能否读取收藏 / 喜欢列表 |
| 抖音风控 | 读取收藏需要登录态，频率和速度要保守；可能需要定期重新登录 |
| X 主页采集 | 网页版接口经常变化，需要预留维护成本；官方数据导出用于获取全部历史 |
| 订阅额度 | 官方文档没有给出订阅模式下批量调用的速率上限，需要实际观察用量并预留切换到 API 的方案 |
| 转写耗时 | 几千条旧视频的本地转写需要几十小时量级，安排在夜间分批执行 |
| 平台条款 | 只读取本人账号数据、仅供个人使用，但各平台条款对自动化读取的态度不一，需要自行评估 |
